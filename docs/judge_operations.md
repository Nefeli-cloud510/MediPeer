# 评委操作说明（本地验收）

前置条件：后端运行在 `http://127.0.0.1:8000`，前端运行在 `http://127.0.0.1:5173`，`.env` 已配置真实模型。

## 1. 整理患者事实

1. 打开 `http://127.0.0.1:5173`，用演示账号登录。
2. 在案例库点击“复制演示模板”中的 `demo_fever_sputum_three_rounds`，进入三栏工作台。
3. 左栏点击“患者信息与原文”，运行“整理患者事实”；结果会区分“患者自述、医生提问未获答、未提及、明确否认、时间性状态”，并允许点击引用定位原文。

预期：出现“患者昨天开始有痰”有原文依据；不出现“目前无发热”被当成患者已确认事实。

## 2. 审阅新草稿

1. 在工作台中栏确认或修改草稿（例如“患者昨天开始有痰，目前无发热。”）。
2. 点击“重新分析/联合审阅”。
3. 右栏查看每句主张的“观点贡献 + 患者依据”：
   - “患者昨天开始有痰”应为同行已提及、患者有依据；
   - “目前无发热”应为缺少患者依据、仅医生提问未获答。
4. 点击右栏证据引用，验证中栏对应原文高亮；点击提示可定位草稿句。

预期：真实模型返回结构与引用通过程序校验；无依据主张显示“缺少依据”，不伪造引用。

## 3. 补录后复核

1. 在接入区补录患者回复，例如“我今天早上发过烧，现在没量。”并保存。
2. 再次运行联合审阅。
3. 右栏“与上一审阅的提示变化”应显示：
   - 有痰相关判断保持；
   - 发热相关提示变化，但“目前无发热”不能仅凭今晨发烧陈述确认或否认；
   - 引用可定位到补录消息“今天早上发过烧”“现在没量”。
4. 修改草稿为“患者昨天开始有痰，自述今晨发热，目前体温未提供。”后再次分析，确认原“目前无发热”提示因改稿解决，而非记录成“患者确认无发热”。

## 4. 导出与嘉宾复现

1. 在历史分析中选择最新运行，点击“导出”。
2. 选择 JSON 或 Markdown；下载文件应包含病例版本、草稿版本、逐主张判断、对应原文、人工处理记录与前后变化。
3. 用两个独立会话打开同一模板，确认各自修改、分析与导出互不覆盖。

注意：当前验收针对本地运行；外部可访问部署尚未完成，不要把“本地可访问”写成“已部署”。没有人工冻结标签时不做准确率结论。
